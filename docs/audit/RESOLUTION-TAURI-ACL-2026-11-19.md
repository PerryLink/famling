## 0. 结论摘要

1. **Tauri v2 默认行为已核实**：只要注册进 `invoke_handler`，自定义命令默认对所有窗口/WebView 开放；只有应用显式提供 `AppManifest::commands` 并让 capability 引用对应 `allow-<command>` 权限后，runtime 才按 capability 的 `windows`/`webviews` 标签放行（§2）。
2. **实现**：`build.rs` 用 `tauri_build::try_build(Attributes::new().app_manifest(AppManifest::new().commands(&[...])))` 覆盖**全部 23 个**注册命令；tauri-build 自动生成 `permissions/autogenerated/*.toml`（23 个 `allow-*` + 23 个 `deny-*`）。capability 拆为 1 个共享窗口控制 + 6 个按窗口的命令 capability；`tauri.conf.json` 用 `app.security.capabilities` 显式列出这 7 个（新增未列入的 capability 文件不会生效，fail-closed）。
3. **最小暴露矩阵**（详见 §3.2）：`protect_text`/`unprotect_text`/`clear_save_backup`/`read_advisers_brief`/`fetch_deepseek_share`/`voice_*`/`set_pet_hit_regions` + consent 门 4 命令**只授予 pet-shell（`main`、`pet`）**；`write_save`/`read_save`/`delete_save` 授予 pet-shell 与各游戏/bench 窗口，但 Rust 侧另有 `require_save_window(label, slot)` slot 白名单（task-43），两层叠加；游戏窗口只拿自己的 DLC/全屏/基准命令；`read_pack_manifest`/`steam_status`（无前端调用者）**不授予任何窗口**。
4. **构建期门禁**（每次 `cargo check/build/test` 生效，CI 的 `rust-tauri-tests` 作业也会跑）：`build.rs` 校验 `COMMANDS` == `src/main.rs` 的 `generate_handler![...]`、capability 文件矩阵与 `CAPABILITIES` 一致、敏感命令只出现在 `pet-shell.json`。两条负向实验证明漂移会**让构建失败**（§4.2）。
5. **运行时验证**：release + `--features custom-protocol` 构建后，用 CDP 在 7 个窗口 label（`main`/`pet`/`aquarium`/`town`/`stall`/`farm`/`bench`）执行 121 项“允许/拒绝”断言，**7/7 模式全部通过**；拒绝信息为 `Command <name> not allowed by ACL`（§4.4）。
6. **剩余 blocker**：`rust-tauri-tests` 目前 `continue-on-error`（不阻塞合并）；`permissions/autogenerated/` 构建产物提交策略待定；同源 localStorage 共享（P1-2 子项 2）不在 ACL 能解决的范围；另有若干 P2（§5）。

## 2. Tauri 2.12 机制研究（本地 crate 源码 + 官方文档）

本机依赖版本（`app/tauri/src-tauri/Cargo.lock`）：`tauri 2.12.5`、`tauri-build 2.7.4`、`tauri-utils 2.10.2`。源码证据取自 Windows 侧 Cargo registry（`<private-path>/.cargo/registry/src/index.crates.io-*/`，只读，未写入/未改凭据）。

### 2.1 默认全开与 `AppManifest::commands`

- 官方文档：“By default, all commands that you registered in your app (using the `tauri::Builder::invoke_handler` function) are allowed to be used by all the windows and webviews of the app. To change that, consider using `AppManifest::commands`.”（<https://v2.tauri.app/security/capabilities/>）
- `tauri-build-2.7.4/src/acl.rs:102-107`：`AppManifest::commands()` 的文档——列出的命令会**自动生成** `allow-$command` / `deny-$command` 权限（`$command` 为 snake_case）。
- `tauri-build-2.7.4/src/acl.rs:278-338`：`autogenerate_command_permissions()` 对每个命令写 `./permissions/autogenerated/<command>.toml`，内容为 `commands.allow = ["<command>"]` 与 `commands.deny = ["<command>"]`；**权限标识符是 `command.replace('_', '-')`**（例如 `unprotect_text` → `allow-unprotect-text`，capability 里必须写 slug 形式）。
- `tauri-build-2.7.4/src/acl.rs:421-426`：只有 app manifest 有内容（命令/permission/set/default 任一）时才把 `__app-acl__` 放进 ACL manifest。

### 2.2 capability 如何引用应用命令权限

- `tauri-build-2.7.4/src/acl.rs:357-372`：capability 里的 permission 标识符按 `:` 前缀解析；**没有前缀的标识符归到 app ACL**（`APP_ACL_KEY`）。因此 capability 里写 `"allow-unprotect-text"`（无 `app:` 前缀）即可。
- `tauri-build-2.7.4/src/acl.rs:341-405`：构建期校验 capability 引用的 permission 是否存在，写错直接构建失败并给出候选提示。
- `tauri-utils-2.10.2/src/acl/resolved.rs:190-222`：app ACL 的 `commands.allow` 直接映射为命令名（插件命令才是 `plugin:<name>|<cmd>`）；`tauri-2.12.5/src/ipc/authority.rs:462-489` 在 runtime 用 `windows`/`webviews` 的 label glob 过滤。

### 2.3 runtime 的拒绝路径（为什么修复后“未授予=不可调”）

- `tauri-2.12.5/src/ipc/authority.rs:132-134`：`has_app_manifest()` 返回 `resolved_acl.has_app_acl`；该值来自 `Resolved` 构建时的 `has_app_manifest(acl)`（`resolved.rs:250`，即 ACL 里是否存在 `__app-acl__`）。
- `tauri-2.12.5/src/webview/mod.rs:2076-2109`：

  ```rust
  // Check ACL on plugin commands, when the app defined its ACL manifest,
  // or when the request comes from a non-local (remote) origin.
  if (plugin_command.is_some() || has_app_acl_manifest || !is_local)
      && invoke.acl.is_none()
  {
      // release builds: invoke.resolver.reject(format!("Command {} not allowed by ACL", request.cmd))
      return;
  }
  ```

  即：**一旦 app 定义了 ACL manifest，任何“未被 capability 授予”的自定义命令（包括没写进 `COMMANDS` 的）都会被拒绝**——fail-closed。这也是为什么 `COMMANDS` 必须与 `generate_handler!` 完全同步（§3.4 门禁）。

### 2.4 `app.security.capabilities` 显式白名单

- `tauri-utils-2.10.2/src/config.rs:3100-3141`：`app.security.capabilities` 为空时自动加载 `capabilities/` 下全部文件；**非空时只加载列出的 identifier**（字符串引用）或内联 capability。本任务用它做第二道“新 capability 默认不生效”的防线（§3.5）。

### 2.5 两个实现细节（避免踩坑）

1. **构建会写源码目录**：`autogenerate_command_permissions` 的目标路径是相对 build script 工作目录的 `./permissions/autogenerated`（`tauri-build/src/acl.rs:281`）。生成文件带 `# Automatically generated - DO NOT EDIT!`，本仓库此前没有 `permissions/` 目录；构建后新增 `src-tauri/permissions/autogenerated/*.toml`（未跟踪，见 §5-B3）。
2. **`cargo build` 与 `tauri build` 的差异**：`tauri build`/官方发布脚本（`scripts/build-tauri-win.bat`、`scripts/release-win.mjs` 调 `npx @tauri-apps/cli build --no-bundle`）会自动启用 `custom-protocol` feature 把 `dist/` 嵌进二进制；直接 `cargo build --release` 时**必须加 `--features custom-protocol`**，否则 release 二进制会去连 `devUrl`（localhost:5173），运行时页面变成 `chrome-error://`（本次运行时探针第一轮就踩到，见 §4.4）。

### 3.3 为什么 chat-import / setup 页不需要单独的 capability

`src/pet/main.ts:2459` 与 `src/pet/desktop-shell.ts:361` 用 `window.open('/chat-import.html','_blank')` 打开导入页，失败时 `window.location.href` 在同窗口导航。Tauri 未注册 `on_new_window` handler 时，wry 的 WebView2 实现会 `args.SetHandled(true)` **拒绝新窗口**（`wry-0.57.2/src/webview2/mod.rs:777-864`；本应用 `main.rs`/窗口 builder 都没有 `.on_new_window(...)`），因此该页面实际在**原本的 `main`/`pet` 窗口**里运行，`pet-shell` capability 已覆盖它需要的 `fetch_deepseek_share`/存档/consent 命令。`setup.html` 不调用 IPC 命令。

### 3.4 构建期门禁（build.rs）

`build.rs` 在 `tauri_build::try_build()` 前后做三组断言，失败即 `panic!("[tauri-acl] ...")` 让构建失败（**没有环境变量跳过开关**；已告知 task-43 owner）：

1. `check_commands()`：解析 `src/main.rs` 的 `generate_handler![...]`，取每个条目的最后一段函数名，与 `COMMANDS` 常量做集合比较；不一致报 `command ACL drift`（多/少都报）。
2. `check_capabilities()`：
   - `capabilities/*.json` 文件集合 == `CAPABILITIES` 期望（多一个文件也失败）；
   - 每个文件的 `identifier`、`windows`、app 权限集合（`allow-*`/`deny-*`，忽略 `core:*`）与期望一致；
   - 每个 `COMMANDS` 条目必须被某个 capability 授予，或在 `UNGRANTED_COMMANDS` 里显式声明“故意不可达”；
   - `PET_ONLY_COMMANDS` 只能由 `pet-shell.json` 授予（该文件 windows 固定 `main`/`pet`）。
3. `println!("cargo:rerun-if-changed=src/main.rs")`：命令表变化时强制重跑 build script（tauri-build 自身只 watch config/capabilities）。

> `build.rs` 用极简 JSON 字符串扫描（`json_string` / `json_string_array`）读取 capability，避免给 build-dependencies 增加 `serde_json`。capability 文件由本任务维护、格式受控；若未来改成含转义引号的复杂 JSON，应改用 `serde_json` 作为 build-dependency（§5-R6）。

### 3.5 `tauri.conf.json`

```json
"security": {
  "csp": "...不变...",
  "capabilities": ["default", "pet-shell", "game-aquarium", "game-town", "game-stall", "game-farm", "bench"]

```

## 附录 A：建议后续加入的静态测试（本任务未写 tests/，留给 lead/task-44）

`build.rs` 门禁已经覆盖同等不变量；若需要在 `npm test` 侧也有独立防线，可新增 `tests/tauri-acl.test.ts`（~60 行，纯静态读取）：

```ts
import test from 'node:test'
import assert from 'node:assert/strict'
import { readFileSync } from 'node:fs'
import { fileURLToPath } from 'node:url'

const root = new URL('..', import.meta.url)
const read = (p: string) => readFileSync(fileURLToPath(new URL(p, root)), 'utf8')
const json = (p: string) => JSON.parse(read(p))

const buildRs = read('app/tauri/src-tauri/build.rs')
const mainRs = read('app/tauri/src-tauri/src/main.rs')
const conf = json('app/tauri/src-tauri/tauri.conf.json')
const caps = ['default', 'pet-shell', 'game-aquarium', 'game-town', 'game-stall', 'game-farm', 'bench']
  .map((id) => json(`app/tauri/src-tauri/capabilities/${id}.json`))

const handler = /generate_handler!\[([\s\S]*?)\]/.exec(mainRs)?.[1] ?? ''
const registered = handler.split(',').map((e) => e.trim().split('::').pop()!).filter(Boolean)
const commandsBlock = /const COMMANDS: &\[&str\] = &\[([\s\S]*?)\];/.exec(buildRs)?.[1] ?? ''
const declared = [...commandsBlock.matchAll(/"([a-z_]+)"/g)].map((m) => m[1])

test('every generate_handler command is in the ACL command list', () => {
  assert.deepEqual([...registered].sort(), [...declared].sort())
})

test('pet-only commands never leak into game/bench windows', () => {
  // delete_save/read_save/write_save are slot-scoped in Rust (require_save_window),
  // so they are deliberately shared with the game windows; the rest stay pet-only.
  const petOnly = [
    'read_advisers_brief', 'protect_text', 'unprotect_text', 'clear_save_backup',
    'voice_status', 'voice_synthesize', 'voice_cache_clear', 'voice_asr',
    'fetch_deepseek_share', 'set_pet_hit_regions',
    'record_host_consent', 'revoke_host_consent', 'grant_host_voice_consent', 'host_consent_status',
  ]
  for (const cap of caps) {
    if (cap.identifier === 'pet-shell') continue
    for (const command of petOnly) {
      assert.ok(!cap.permissions.includes(`allow-${command.replace(/_/g, '-')}`), `${cap.identifier} must not grant ${command}`)
    }
    assert.ok(!cap.windows.includes('main') && !cap.windows.includes('pet'), `${cap.identifier} must not target the pet shell`)
  }
  for (const id of ['game-aquarium', 'game-town', 'game-stall', 'game-farm', 'bench']) {
    const cap = caps.find((c) => c.identifier === id)!
    for (const slotScoped of ['delete_save', 'read_save', 'write_save']) {
      assert.ok(cap.permissions.includes(`allow-${slotScoped.replace(/_/g, '-')}`), `${id} must grant ${slotScoped}`)
    }
  }
})

test('tauri.conf.json enables exactly the intended capabilities', () => {
  assert.deepEqual(conf.app.security.capabilities, ['default', 'pet-shell', 'game-aquarium', 'game-town', 'game-stall', 'game-farm', 'bench'])
})
```
