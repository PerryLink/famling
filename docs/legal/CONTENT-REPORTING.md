## 1. 受理范围

| 类型 | 示例 | 受理 | 公开 GitHub 表单是否合适 |
|---|---|---|---|
| 版权 / 商标侵权 | 盗用官方美术/角色/音频、冒用名称或 Logo、抢注后反向投诉 | ✅ | 可以（不鼓励粘贴未公开源文件） |
| 隐私 / 肖像 / 名誉 | 真人换脸、开盒/泄露个人信息、诽谤、非自愿私密影像 | ✅（安全优先） | **不适合**：涉及个人隐私/私密影像请走邮件或报警 |
| 违法 / 有害内容 | 未成年人性化、色情、仇恨、暴力威胁、教唆自伤、诈骗 | ✅（零容忍） | **不适合**：紧急/涉刑先报警或 12377 |
| 恶意包 / 安全 | 恶意代码、窃密、伪造签名/哈希、供应链投毒 | ✅ | **不适合**：漏洞利用细节请走邮件 |
| 冒充官方 | 假官方账号/店铺/公告，冒充 PerryLink、famling 或 DeepSeek | ✅ | 可以（不要公开无关个人信息） |
| 许可 / 署名争议 | 署名缺失、许可不符、AI/素材来源声明缺失 | ✅（优先补正） | 可以 |
| 一般观点批评 / 差评 | 主观评价、非官方同人 | ❌ 不受理 | 不适合；不审查批评 |
| 第三方平台内容 | 其他网站/商店/社交平台上的内容 | ⚠️ 只能转交/协助 | 不适合；请先使用该平台举报入口 |

**零容忍**（触发即优先隔离/下架并评估报告义务）：未成年人性化/CSAM、非自愿私密影像、可信暴力威胁、教唆自伤自杀、诈骗、开盒/隐私侵害、恶意包/伪造签名、冒充官方/DeepSeek。

## 2. 应用内入口（本版本已实现）

入口（两处，同一个本地对话框）：

- 桌面设置 → **关于 / 声明 / 数据控制** → **举报与下架…**
- **关于与声明** 面板 → **举报与下架…**

对话框提供：

1. **受理范围**：官方内容 vs 第三方平台；一般批评不受理；紧急渠道提示。
2. **分类与所需证据**：选择类型后显示该类示例和证据要求；另有通用证据清单。
3. **反通知说明**：临时下架不等于认定侵权；被举报方可提交反通知；**没有自动恢复程序**，由人工审查。
4. **可复制举报模板**：Markdown 文本，字段与 GitHub 表单一致。
5. **本地 JSON 导出**：`content-report.json`，只包含用户自己填写的内容和固定的 schema/渠道信息。
6. **打开公开 GitHub 表单**：仅在你点击按钮时打开 `https://github.com/PerryLink/famling/issues/new?template=content-report.yml`；是否提交由你决定。
7. **复制 GitHub 表单地址**：窗口打不开时可手动粘贴。
8. **邮件渠道**：涉隐私/未成年人/非自愿私密影像/漏洞细节请发 `novelnexusai@outlook.com`，不要把敏感证据放进公开 issue。

### 2.1 “不自动上传/不收集”的具体含义

- 打开对话框、选择类型、输入文字、预览模板**不会**发起任何网络请求；代码中没有 `fetch`/`XMLHttpRequest`/`sendBeacon`。
- **不会读取**存档、记忆、账号、设备标识、日志或聊天记录；表单默认全部为空，不预填个人信息。
- 用户输入只存在于当前页面内存；**不写入**存档、localStorage、日志或远端；“导出 JSON”只在本机触发下载，“复制”只写系统剪贴板。应用**不会自动上传**、不会自动发送邮件或 issue。
- 只有点击“打开 GitHub 表单/复制地址”才打开外部页面/剪贴板；之后是否提交、提交到 GitHub 由用户自行决定，适用 GitHub 自己的隐私与内容政策。
- 本流程**没有**后台审核队列、自动分类、自动下架或自动通知；不会声称“已受理/已处理”，除非人工确认。

> 源码位置：`src/pet/content-reporting.ts`；表单：`.github/ISSUE_TEMPLATE/content-report.yml`。

## 3. 提交前证据清单（越完整处理越快）

1. **身份与联系方式**：姓名或机构、有效邮箱；代理人附授权说明。只提供处理所需的最少信息。
2. **权利/受影响权益**：著作权、商标、肖像、隐私等依据；登记号、首次发布记录、授权链、原创源文件/时间戳（如适用）。
3. **精确定位**：逐项列出 URL、仓库路径、包 id、版本、文件名、sha256、截图（含时间与上下文）；不要只给一个笼统链接。
4. **可核验证据**：截图/源文件/复现步骤；声称“盗用”时说明原作品与对应关系。
5. **具体请求**：删除、下架、更正署名、断开链接、停止传播、转交平台等。
6. **真实性声明**：确认材料真实、善意提交；理解错误通知可能承担法律责任（《民法典》通知—删除规则下的错误通知责任由律师最终确认）。
7. **可转达性**：同意在必要范围向被投诉方转达材料要点；涉隐私可先不勾选，由人工联系确认并脱敏。

> 涉及 CSAM、非自愿私密影像、可信人身威胁、诈骗等，请**保留证据但不要公开传播**，先报警/12377；本流程不要求也不建议把此类材料贴到公开 issue。

## 5. 人工处理流程（内部目标，非承诺）

| 步骤 | 动作 | 内部目标（工作日；best effort） |
|---|---|---|
| S1 收件确认 | 人工查收，回复补材料清单（如需要） | 3 个工作日 |
| S2 初审 | 判断类型、管辖、是否属官方渠道；紧急项立即升级，不等待普通队列 | 10 个工作日 |
| S3 临时措施 | 明显侵权/违法/安全风险 → 人工决定临时下架/隔离；争议内容也可先隔离止损 | 初审后 5 个工作日 |
| S4 转达被投诉方 | 人工脱敏后转达通知要点，给申辩机会（涉隐私/安全可不转达并说明） | 与 S3 同步或尽快 |
| S5 申辩/反通知审查 | 综合双方材料、授权/合理使用依据与法律意见 | 10 个工作日 |
| S6 终局决定 | 恢复/永久下架/封禁/转平台；向双方说明理由（不泄露他人隐私） | 20 个工作日 |
| S7 归档 | 记录处理结果、证据范围、是否需律师；按保留规则清理 | 结案后 30 日内 |

**说明**：工作日按项目所在时区计算；材料不完整、需要律师意见、跨境/平台程序、不可抗力或安全事件可延长，延长时尽量告知；**不承诺一定在目标时限内完成，也不承诺任何特定结果**。若法律/平台规则给出更短或更长程序，按法律/平台规则执行。

## 6. 临时下架与反通知（人工，不自动）

1. **临时下架 ≠ 认定侵权**：目的是止损与调查；恢复需要人工结论。
2. **反通知**：被举报方可说明授权、合理使用（法定情形）或其他不侵权依据，并提交与通知同等级的材料与真实性声明。
3. **没有 DMCA 式自动恢复**：反通知由人工审查；不承诺恢复时间或结果；仍争议时建议走平台程序/律师函/诉讼。
4. **不泄露**：不得因反通知泄露原通知人身份/隐私；对外公告需脱敏。
5. **重复侵权/恶意发布**：人工评估后可永久拒绝服务或列入黑名单，并保留追责权利。

## 7. 对发布方的处理级别（人工裁量）

| 级别 | 情形 | 动作 |
|---|---|---|
| L1 | 署名/许可字段缺漏 | 通知补正；限期内未改再评估下架 |
| L2 | 违反内容政策（非零容忍） | 下架/隐藏 + 警告；重复则升级 |
| L3 | 零容忍 / 恶意代码 / 冒充官方 / 严重侵权 | 优先下架/隔离 + 封禁/转平台/依法报告 |
| L4 | 伪造签名/证据、恶意举报 | 拒绝受理/封禁 + 保留追责 |

## 8. 证据与隐私

1. 材料仅用于处理争议；按最小必要保存，不公开个人隐私、私密影像或未生效法律意见。
2. **公开 GitHub issue 是公开的**：不要把身份证号、住址、电话、未公开源文件、未成年人信息、非自愿私密影像或可直接利用的漏洞细节放进去；这些走邮件/安全渠道。
3. 导出 JSON 只在本机生成，应用不上传；用户自行决定保存/发送，发送后适用接收方（邮件/GitHub）的隐私政策。
4. 涉刑事线索（CSAM、诈骗、人身威胁）依法向公安机关/平台报告，不自行“私了”。
5. 保留期限、跨境传输与个人信息处理细节仍待律师确认；在确认前按最小必要与短期保留执行。

## 9. 滥用举报

- 明显虚假、恶意或骚扰性通知：人工驳回并留存记录；造成损失的可依法主张责任。
- 同一通知人反复提交无依据通知：限制受理并要求补充材料。
- 我方人员处理错误：内部复核 + 更正；重大权益事项转律师。
