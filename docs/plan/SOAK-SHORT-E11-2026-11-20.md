## 2. 为什么需要这个 harness

1. **现有 soak 不进 UI**：`scripts/soak.ts` 是内核模拟（300 地块 / 36k tick），不经过菜单、缩放、内容窗口、存档、角色包安装；`scripts/soak-tauri.ps1` / `run-soak-24h.cmd` 需要 Windows 原生 24h 墙钟（仍未完成，见 `docs/plan/EXECUTION-STATUS-2026-11-20.md` MB-113），本任务**不去伪造**它。
2. **E11 GUI 冒烟只跑一次**：`scripts/gui-cdp-smoke.mjs` 是 5 个场景的一次性冒烟；本 harness 把这 5 类操作做成**可循环 + 周期采样**的压力回路，用来观察短时内存/FPS/异常/窗口泄漏。
3. **可重复、可审计**：一条命令 + JSON 报告 + markdown 摘要 + 截图；失败退出码 1，环境问题退出码 2；默认值短小（60s），可显式拉长。

## 3. 五个循环场景

| id | 真实操作 | 完成判据 |
| --- | --- | --- |
| `menu` | 右键打开根菜单 → 读取根项 → Escape 关闭 | 菜单 open→closed 且根项 ≥4 |
| `scale` | 设置对话框 → 点整体缩放滑杆（80%/60% 交替）→ 断言 CSS 变量/持久化 → 恢复默认 → Escape | 状态/变量/存储一致且复位到 2× |
| `content-window` | `window.open` 打开 content-shell 页 → 等 hub open → Escape 回 home → 关闭窗口 | 4 tab、hub open/home/close 全流程且目标消失 |
| `save` | 菜单 → 更多 ▸ → 保存 | 气泡「记下了。」+ localStorage 主槽非空 |
| `pack-install` | 内容包 tab → 真实 zip 输入 → 3 项声明 → 安装 → 启用 → 卸载确认 | 登记行出现→启用请求完成（应用或诚实未应用）→行删除 |

每个场景在 `runStep` 中隔离：单场景失败记入 `stepFailures`（含 `evidence`），尝试清理残留页面目标后继续后续场景与后续循环；gate 会因失败而判定 FAIL。

## 4. 指标、gate 与边界

### 4.1 采样

- **内存**：CDP `Performance.getMetrics`（`JSHeapUsedSize`/`JSHeapTotalSize`/`Nodes`/`Documents`/`LayoutCount`/`RecalcStyleCount`），每次循环开始/结束各采一次；每循环记录 `samples[i].heapBefore/heapAfter`。
- **FPS**：页面内注入 `requestAnimationFrame` 计数器，每循环开始采样 **400ms**；仅当 `document.visibilityState === 'visible'` 且帧数增量为正时记为有效样本（否则记录 `fps: null`，不伪造 0/60）。
- **错误**：每个 CDP target 订阅 `Runtime.exceptionThrown`、`Runtime.consoleAPICalled(error/warning)`、`Log.entryAdded(error/warning)`、`Inspector.targetCrashed`、`Page.javascriptDialogOpening`；错误计数进 gate，warning 只记录。
- **延迟**：每场景每次操作的墙钟耗时 → `min/p50/p95/max/mean`。
- **泄漏/残留**：结束时枚举页面 target，除 bootstrap 与 pet 之外的页面数必须为 0。

### 4.2 gate（`scripts/lib/soak-short-metrics.ts` 单源，纯函数、有单测）

| gate | 阈值 |
| --- | --- |
| `iterations` | `>= --iterations` 或 `>= --min-iterations`（默认 2） |
| `scenario:<id>` | 每个选中场景完成次数 `>= iterations` |
| `scenario-failures` | `= 0` |
| `uncaught-exceptions` / `crashes` / `console-errors` / `log-errors` / `page-dialogs` | 全部 `= 0` |
| `leftover-targets` | `= 0` |
| `fps-samples` / `fps-floor` | 有效 fps 样本 ≥1；中位数 ≥ `--min-fps`（默认 25） |
| `heap-growth` / `heap-peak` | JS 堆首末增长 ≤ `--max-heap-growth-mb`（默认 64 MB）；峰值 ≤ `--max-heap-peak-mb`（默认 800 MB） |

阈值语义：这些是**短时 smoke 级** sanity check。64 MB 的堆增长额度是给渲染进程 LC/GC 抖动留的余量；**短时 JS 堆趋势不能证明 24h 无泄漏**，报告与摘要都写明了这一点。

## 5. 如何运行

前置：

1. `npm run build` 产出 `dist/`（脚本会拒绝缺失或**比 `src/`/`public/` 旧**的 dist）；
2. Node ≥ 22（`tsx` 是 devDependency，用于直接跑 TS）；
3. 本机 Chrome/Chromium（`--chrome PATH` 或 `CHROME_PATH` 覆盖探测）；WSL 需 WSL2 mirrored networking，或直接在 Windows 运行；
4. 脚本启动时把 `dist/` 复制为 `run-*/dist-snapshot` 并校验 `pet.html` sha，**整轮只从 snapshot 提供页面**，避免并发构建/其他进程改动 dist 污染结果（成功运行后自动删除 snapshot；失败时保留以便排查）。

```bash
npm run build
node --import tsx scripts/soak-short.ts                              # 默认 60s，5 个场景
node --import tsx scripts/soak-short.ts --duration 120s --verbose
node --import tsx scripts/soak-short.ts --iterations 5              # 固定 5 轮（调试）
node --import tsx scripts/soak-short.ts --scenarios menu,save       # 只跑子集
node --import tsx scripts/soak-short.ts --out artifacts/soak-short/my-run --keep-profile
node --import tsx scripts/soak-short.ts --help
```

- 退出码：`0` 全部 gate PASS；`1` gate/场景失败；`2` 环境/用法错误（dist 缺失/过期、无 Chrome、watchdog 等）。
- 产物：`<out>/report.json`（机器可读，含 `not24h: true`、`samples`、`gates`、`diagnostics`、`limitations`）、`report.md`、`soak.log`、`01-pet-ready.png`/`02-final.png`（失败时含 `failure-*.png`）；并更新 `artifacts/soak-short/latest.json`/`latest.md`。
- **默认不跑**：`tests/soak-short.test.ts` 断言 `soak-short` 不在 `package.json` scripts、也不在 `scripts/ci.mjs`；CI 不安装/启动浏览器。

## 6. 本轮实测中发现的问题（诚实记录，未在本任务修复产品代码）

1. **内容窗口自动打开 hub 的偶发时序失败**：在快速连续开关内容窗口的压力下，出现过 content window 正常启动（标题/首页正确）但 `#content-hub-root` 一直 `closed` 的情况。注入的 boot trace 显示：约 197ms 两次 `home.hidden=true`（两次 showRoute）、202ms `home.hidden=false`（某条路径 showHome）、203ms 内容运行时/IndexedDB 初始化完成，此后 hub 未再打开；无 console error/exception。
   - 复现记录：run-20261120-060624（60s，第 2/6 轮失败）；更早 run-20261120-055426（第 2/3 轮失败）。trace 与截图保存在失败 run 的 `report.json` / `failure-content-window-*.png`（失败时保留 dist snapshot）。
   - 本 harness 的处置：关闭内容窗口后等待 **300ms** 再做下一轮（模拟真实用户节奏，避免毫秒级 close→open）；若仍失败，自动通过首页「内容与中心…」按钮重试一次，并在 `report.diagnostics` 记 `kind=recovery`（报告 `derived.recoveries` 计数），**不隐藏**该异常。60s 证据轮 0 次触发；120s 复跑 34 轮中触发 **1 次**并被恢复（`recoveries=1`，`report.json` 含 `recovery`/`recovery-trace` 诊断与 boot trace）。
   - **根因已定位并修复（2026-11-20 task-120）**：`src/pet/content-runtime.ts` 的 `ensureContentRuntime()` 在 IndexedDB/asset store/hub 完成前就发布了 `contentRuntime`，内容窗口 boot 与 `initializeApp()` 的 eager 目录加载并发时拿到半成品 runtime（`hub === null`），`openContentHubInWindow()` 诚实降级返回 false → `presentContentWindowRoute` fallback `showHome()`，此后 hub 不再自动打开且无 console error。修复为“只发布初始化完成的 runtime”+ 2 个确定性 Node 回归测试；`npx tsc --noEmit` / `npm test`（1771/1771）/ `npm run build` 全绿，本 harness 60s（23 轮）与 120s（45 轮）复跑均 `recoveries=0`。详见 `docs/plan/CONTENT-WINDOW-HUB-RACE-2026-11-20.md`。本任务 harness 的 300ms settle + 恢复重试作为观测手段保留；本报告 §6.1 的旧数字仅代表修复前。
2. **一次 404 干扰**：更早的一次运行中 content window 主文档拿到 404，定位为运行期间**并发构建清空 `dist/`**（当时尚无 snapshot）；已用 §5.4 的 dist snapshot 隔离，此后未再出现。

## 7. 明确不覆盖 / 不得宣称

1. **不是 24h**：本脚本从不模拟/快进 24h，也**不伪造** 24h 数据；报告 `not24h: true`、`durationMs` 是真实墙钟。24h native soak 仍缺（`artifacts/tauri-soak-24h.json` 不存在）。
2. **不是 Tauri/WebView2**：不启动 Tauri 宿主，不验证原生透明窗口/托盘/单实例/Rust `quit_app`/DPAPI 存档；只跑浏览器 fallback。
3. **不是 GPU/桌面帧率**：`headless=new` + `--disable-gpu` + 禁用后台节流；这里的中位数 fps 只说明 rAF 回路可测，不是桌面合成/GPU 表现。
4. **不是泄漏证明**：JS 堆来自 `Performance.getMetrics` 的渲染进程 JS 堆，不是 native/private bytes；短时趋势不能证明长时无泄漏。
5. **角色包 loop 不是渲染验收**：使用合成 1x1 占位帧 zip，只覆盖安装器/IndexedDB/注册表/启用请求/卸载清理；真实角色包渲染与 hero 热切换需在 Tauri/真实资产下另行验证。
6. **只对本机/本次 dist**：报告记录 HEAD、dirty、dist sha、Chrome 版本、时间；不得引用为“发布验收/跨机器结论”。
7. 不联网、不读真实用户 `%APPDATA%`/localStorage：一次性 Chrome profile 在 artifacts 下，结束/失败都会杀 Chrome 并清理 profile（`--keep-profile` 可选保留）。

## 8. 维护指南

- 场景单一源：`scripts/lib/soak-short-metrics.ts` 的 `SCENARIO_IDS`/`SCENARIO_LABELS`；脚本里的 `SCENARIO_ACTIONS` 映射到具体实现。新增场景要同时更新测试与本文档。
- 阈值/gate：只在 `evaluateGates()` 里改，并为每个 gate 补“失败必须翻红”的单测；不要把短时 gate 提高成“24h 验收”。
- 保持 `not24h: true` 与 `limitations` 字段；任何报告/文档都不得出现“24h 已过”的表述。
- 若未来把本 harness 接入 CI：不可行——CI 无可信浏览器；若要变成必跑，应改为 Playwright/真实 WebView2 的独立流水线并单独评审。
- 与旧脚本的关系：`scripts/soak.ts`（内核模拟）/`soak-simple.ps1`/`soak-tauri.ps1`（native 采样）/`scripts/soak-analyze.mjs`（24h JSON gate）保持原样；本脚本是新增的“浏览器 UI 短时循环采样器”，三者不互相替代。
